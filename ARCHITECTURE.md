# Architecture

EunomiaSync keeps `AGENTS.md` files consistent across many projects. This
document describes how the codebase is laid out and how the pieces talk to
each other. Everything marked **planned** is not implemented yet.

## Overview

- **Backend:** Rust, organized as a Cargo workspace.
- **Desktop shell:** Tauri 2 (`src-tauri`).
- **Frontend:** Vue 3 + TypeScript, built with Vite, styled with Tailwind CSS
  v4, state managed with Pinia.
- **Storage:** SQLite via `rusqlite` with embedded SQL migrations.
- **Typed IPC:** `tauri-specta` generates TypeScript bindings from Rust
  commands; the generated `src/bindings.ts` is committed.

## Workspace layout

```text
crates/
  eunomia-core/            # Core library, no Tauri dependency
    src/storage.rs         #   SQLite storage + migrations   (working)
    markdown               #   Markdown processing           (planned)
    diff                   #   Text diffing                  (planned)
    sync                   #   AGENTS.md sync engine         (planned)
    watch                  #   File watching                 (planned)
    migrations/            #   Embedded SQL migration files
src-tauri/
  src/commands.rs          # Tauri commands (via tauri-specta)  (working)
  src/lib.rs               # App builder, specta registration   (working)
  state                    # Managed app state                  (planned)
src/                      # Frontend
  bindings.ts              # GENERATED by tauri-specta, committed
  App.vue                  # Root view                           (working)
  views/, stores/          # Vue views / Pinia stores            (planned)
```

`eunomia-core` is deliberately independent of Tauri so that storage,
markdown, diff, sync, and watch logic can be tested without a UI layer
(see DECISIONS.md D-006). `src-tauri` is a thin shell: commands, managed
state, and specta wiring.

## IPC contract

Rust commands are registered through `tauri-specta`:

1. A command in `src-tauri/src/commands.rs` is annotated with
   `#[tauri::command]` and `#[specta::specta]`.
2. The command is added to `collect_commands![...]` in `src-tauri/src/lib.rs`.
3. On debug builds the specta `Builder` exports `src/bindings.ts`
   (`specta_typescript::Typescript`). The file is **committed** so the
   frontend type-checks and lints without a Rust toolchain; it is excluded
   from ESLint and Prettier because it is generated.
4. The frontend calls `commands.greet(...)` from `src/bindings.ts`.

**Rule: no raw `invoke()` calls in the frontend.** Always use the generated
`commands` (see DECISIONS.md D-003).

## Storage

SQLite is accessed with `rusqlite` (feature `bundled`, so no system SQLite
is required) and schema evolution uses `rusqlite_migration`
(DECISIONS.md D-002). Migration files live in
`crates/eunomia-core/migrations/*.sql`, are embedded with `include_str!`,
and applied by `storage::run_migrations(&mut Connection)`, which brings any
database to the latest schema version. Tests run against in-memory SQLite
through the public API only.

## Config

Configuration format is TOML (serde + `toml`), per DECISIONS.md D-001.
**Planned** — not implemented yet.

## Watcher

File watching uses `notify` with debouncing through `notify-debouncer-full`
(DECISIONS.md D-004). **Planned** — not implemented yet. On Linux, the
`fs.inotify.max_user_watches` limit must be respected; hitting it should
surface as a clear, actionable error message.

## Updater

Auto-updates are planned via `tauri-plugin-updater` (DECISIONS.md D-005).
**Planned** — signing keys and the update endpoint are separate tasks; not
part of the MVP.

## Testing strategy

| Level       | Scope                                 | Tooling / command                                    |
| ----------- | ------------------------------------- | ---------------------------------------------------- |
| Unit        | Rust crates and Vue components        | `cargo test --workspace` / `npm run test` (Vitest)   |
| Integration | `eunomia-core` storage & migrations   | `cargo test -p eunomia-core` (in-memory + file DB)   |
| API         | Tauri commands over mock IPC runtime  | `cargo test -p eunomia-sync` (`tauri::test` mocks)   |
| E2E         | Browser scenarios against Vite server | `npm run e2e` (Playwright, DECISIONS.md D-007)       |
| Smoke       | App builds on all three platforms     | CI `build` matrix: `tauri build --debug --no-bundle` |

## CI

GitHub Actions workflow (`.github/workflows/ci.yml`) runs five jobs:

- **lint** — `cargo fmt --check`, `cargo clippy -D warnings`, ESLint,
  Prettier, TypeScript.
- **test** — `cargo test --workspace`, Vitest.
- **deny** — `cargo-deny` (licenses, advisories, duplicate crates).
- **e2e** — Playwright against the Vite dev server.
- **build** — `tauri build --debug --no-bundle` on Ubuntu, Windows, and
  macOS.

## Platform notes

- **Linux:** requires `webkit2gtk-4.1` and other GTK packages
  (see `CONTRIBUTING.md`); the watcher must handle `inotify` watch limits.
- **Windows:** renders through WebView2 (bundled with Windows 10+).
- **macOS:** requires the Xcode Command Line Tools for the Rust/TKG build.
